# Subscription flow before changes — 10 September 2026

The platform console uses JdbcTemplate services and record DTOs, rather than JPA subscription entities. Flyway V40 created subscription_plans, normalized subscription_plan_features (composite primary key), institute_subscriptions, institute_feature_overrides, platform_settings, platform_invoices and platform_audit_logs. V42 supplies platform_current_subscriptions: one ranked current/latest row per institute with request-time expiry. A partial unique index permits at most one TRIAL/ACTIVE/PAST_DUE row. Platform controllers require SUPER_ADMIN and use separate platform authentication.

PlansPage already lists database plans, opens a basic modal and saves through POST /platform/plans. It batches feature writes and includes a version predicate, but allows backend code changes, lacks default-plan protection and specific conflict responses, rejects zero limits, exposes ARCHIVED, omits yearly price, and renders zero as unlimited. SubscriptionsPage is a separate directory with hardcoded plan filters, fixed page size, no summary, no expiry/cycle filters and no plan creation entry. InstituteDetailsPage provides history and a basic assignment form but offers inactive plans, omits visible errors and price autofill, and invalidates only three queries.

PlatformConsoleService cancels current subscription rows and inserts a new history row transactionally. It snapshots subscription amount separately from plan prices and platform invoices; school fees are separate. Assignment currently uses an advisory lock and the partial unique index but no stale-form check or explicit price-override audit. History sorts by creation timestamp alone. Features are evaluated dynamically from the plan plus institute overrides; no copy is made on assignment. FeatureCode is the central Java registry, although two entitlement SQL statements duplicate its strings.

PlanLimitService checks non-archived students/teachers and ACTIVE user accounts using per-institute advisory locks. Create/import services call it inside transactions. Reactivation and subscription-access checks need review. Student accounts are part of maxUsers. Storage has no trustworthy per-institute byte accounting and must be displayed as unavailable, not enforced.

PlatformProvisioningService inserts a default trial during institute registration, with hardcoded fallback BASIC/14 and no check for an unsuccessful insert. Platform settings accepts a text plan code. SubscriptionExpiryJob updates ended subscriptions nightly; the current-subscription view also computes expiry during reads. Automatic changes currently lack audit entries.

The dashboard uses the same ModuleCard as College Dashboard. Existing platform panels, modal styling, inputs, status badges and table/pagination patterns will be reused. Existing gateway work and all unrelated workspace edits must be preserved.
